# 单片机测距与蜂鸣器 Proteus 仿真

打开 `Ultrasonic_Proximity_Buzzer.pdsprj`，保持 `Ultrasonic_Proximity.hex` 与工程在同一目录，再点击左下角运行按钮。

本工程由原超声波/LCD 工程扩展而来，原文件未覆盖。保留原器件位置与网络关系，重新生成不受编辑工具支持的旧导线；增加低电平有效 PNP 蜂鸣器驱动、两个阈值按键、上拉电阻及 ECHO 下拉电阻。

## 操作

- US1 的加减按钮调整目标距离；初始距离为 20 cm。
- SW2（K3）将阈值增加 5 cm；SW3（K4）减少 5 cm。点击按钮的上方活动横杆。
- 初始阈值 30 cm；距离进入阈值时显示 `!`；离开到阈值加 3 cm 或更远时显示 `-`。
- 固件来自已编译的 Ultrasonic_Proximity 工程，未改写或重新编译；`main.c` 同步附在目录。

## 新增电路

- P1.5 → R2（1k）→ Q1（2N3906）基极。
- Q1 发射极接 5V，集电极接 LS1；R4（10k）为基极/发射极上拉。
- LS1 另一端接地，R7（100k）提供输出下拉。
- P3.2 接 SW2，P3.3 接 SW3；按下接地，分别由 R5/R6（10k）上拉。
- R8（10k）接 ECHO 与地，解决仿真中释放输入读取为高而报 NO ECHO 的问题。

LS1 使用 Proteus 已安装的 `SPEAKER` 模拟声音模型（100Ω、标称5V），模拟无源蜂鸣器的音频驱动。Q1 为通用 PNP 替代模型；本图不是对开发板蜂鸣器元件、电阻值及声学特性的精确复刻。

## 已验证与边界

在 Proteus 8.17 中实际加载并运行：20 cm/阈值30 cm时显示报警标记；K3将30变为35；K4可将40降为35；42 cm/阈值35 cm时报警标记消失。声音模型在报警时显示活动信号。日志看到的持续消息为超声测量跟踪信息。

没有通过音频采集确认用户电脑实际发声，也没有定量测量音频频率、三档间歇时长和3 cm边界两侧的精确切换。不能将此次仿真验证当作硬件电气/声学验证。

`build_buzzer_project.py` 是重建源码，依赖原本地工程、已安装 Proteus 元件库及原实验使用的 `proteus-api` 文件编辑工具；这些本机路径需要在其他电脑上调整。下载的工程和HEX可直接一起使用，不要求先运行重建脚本。
